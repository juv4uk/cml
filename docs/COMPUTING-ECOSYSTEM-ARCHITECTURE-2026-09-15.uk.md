# Архітектура обчислювальної екосистеми — потоки й залежності (2026-09-15)

![Моя обчислювальна екосистема — архітектура, залежності та потік даних](architecture/computing-ecosystem-architecture.png)

Схема архітектури повного стеку, авторства власника: від семантики Lisp до
заліза. Цей репозиторій (`cml`) — це шар **CML (компілятор для My Lisp)**:
він споживає семантику Lisp і перевірені CPU-профілі від `my-lisp`
(Lisp-форми, семантичні ідентичності/правила, канонічні машинні форми —
`#175`/`#176`) і виробляє цільовий код через frontend, оптимізатор,
кодогенератор і target-абстракцію. Він ніколи не перевизначає значення
мови (`cml#46` — ключовий authority guard для цієї межі).

Повний стек, згори донизу: Користувач/розробник → **my-lisp** (Мова та
семантика, володіє Canon/значенням) → **CML** (цей репо) → Target
Runtime/OS (напр. `wsm-os-lisp`, реалізує ABI) → Залізо. Зовнішні джерела
(документація CPU, стандарти, зовнішні оракули) — лише read-only доказ,
ніколи не семантична влада.

Ця схема — знімок наміру, а не сама по собі авторитетний документ:
`juv4uk/ecosystem#7` (жива крос-репо карта) лишається авторитетним,
оновлюваним на місці джерелом істини про поточне володіння та межі.
