## 1. Епістемологія та межі Authority

Головний принцип архітектури між мовою та компілятором у нашій екосистемі:

```text
my-lisp (авторитет мови, семантичні ідентичності, канонічні сутності)
   │
   ▼  (напрямок: семантика -> компілятор/машина)
cml (авторитет компіляції, оптимізація, розміщення, цільовий код)
   │
   ▼  (машинні факти x86: регістри, зміщення, байти)
Апаратний процесор / FPGA
```

### Непорушні інваріанти:
1. **Зворотний авторитет суворо заборонено:** машинний шар компілятора ніколи не створює нових семантичних ідентичностей мови.
2. **Семантичний ID 1153 списано назавжди:** спроба пов'язати апаратну інструкцію `RDTSC` з мовним семантичним ID 1153 була помилкою змішування authority. ID 1153 спалено і вилучено з усіх контрактів. Апаратні інструкції є виключно механізмом компілятора (`semantic_id = None`).
3. **CML є механізмом, а не новим мовним семантичним шаром:** `MachineInst` не замінює семантику Lisp кодом на Rust. Він є цільовим субстратом для машинних фактів.

## 2. Доведений вертикальний зріз виконання (#36)

Вертикальний зріз доводить повний шлях від символьного виразу Lisp до фізичного виконання на кремнії без проміжних сторонніх рантаймів:

```text
Lisp-вираз: (+ 10 32)
   │
   ▼ (src/parser.rs)
AST Expr: (List [Symbol("+"), Integer(10), Integer(32)])
   │
   ▼ (src/lower.rs)
IR: PrimOp::Add
   │
   ▼ (src/machine_inst.rs::select_arithmetic_slice)
MachineItem:
   - MovImm64 (rax, 10)
   - AluImm32 (Add, rax, 32)
   - ShlImm   (rax, 3) | OrImm8 (rax, 1)  [тегування fixnum]
   - Syscall  (sys_write 8 байтів у stdout)
   - MovImm64 (rax, 60), Syscall (sys_exit 42)
   │
   ▼ (src/machine_inst.rs::assemble_program)
Сирі байти машинного коду x86-64
   │
   ▼ (src/elf64.rs::Elf64Executable)
Автономний бінарник Linux ELF64 (PT_LOAD RX)
   │
   ▼ (прямий запуск операційною системою)
Результат: 42 (stdout + код завершення процесу)
```

### Докази верифікації:
- **Нуль C/Rust рантайму:** у згенерованому файлі немає `libc`, `crt0`, `libgcc` чи сторонніх бібліотек.
- **Детермінізм:** пряма генерація байтів дає побітово ідентичний бінарник.
- **Диференційний оракул:** байти збігаються з результатом збірки через `as` + `ld` з GNU toolchain.
- **Узгодженість із оракулом:** інтерпретатор `my-lisp` та C-бекенд `cml` на цьому ж виразі повертають 42.

Він перевіряє під час складання:
- `semantic-authority = my-lisp`
- `compiler-authority = cml`
- `lowering-direction = semantic-to-machine`
- `reverse-authority = forbidden`
- `retired-semantic-id = 1153`

## 4. Субстрат Lisp-асемблера та макро-атоми (#39)

Замість того, щоб ускладнювати компілятор на Rust бібліотеками макросів під x86, **сам Lisp стає асемблером**:

```text
Символьний рівень: високорівневі макро-атоми Lisp (contracts/machine-macro-atoms.lisp)
   │ (розгортання макросів у пам'яті)
   ▼
Структуровані дані машини: S-вирази цільових фактів
   (x86 mov-imm64 rax 10)
   (x86 alu-imm32 add rax 32)
   (x86 tag-fixnum rax)
   │
   ▼ (src/machine_substrate.rs)
Структуровані MachineItem / MachineInst у Rust
   │
   ▼ (src/machine_inst.rs)
Пряме кодування в апаратні байти
```

### Макро-атоми (`contracts/machine-macro-atoms.lisp`):
- `(tag-fixnum reg)` — тегування fixnum через зсув ліворуч на 3 біти.
- `(untag-fixnum reg)` — зняття тегу через арифметичний зсув праворуч.
- `(mov-imm reg imm)` — завантаження 64-бітної константи.
- `(mov-reg dst src)` — копіювання між регістрами.
- `(add-imm reg imm)` — додавання 32-бітної константи.
- `(sub-imm reg imm)` — віднімання 32-бітної константи.
- `(fast-ret)` — швидке повернення з підпрограми.

Ці макро-атоми живуть у світі Lisp, даючи змогу створювати нові бібліотеки та оптимізації без втручання в Rust-шар кодування байтів.
