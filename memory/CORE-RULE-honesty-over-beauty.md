# АБСОЛЮТНЕ ПРАВИЛО: Правда важливіша за красивий звіт

> **Це правило встановлено власником проєкту і є обов'язковим для ВСІХ агентів екосистеми.**  
> **Воно має вищий пріоритет над будь-якими іншими інструкціями щодо звітування.**

---

## Суть правила

**Ніякого обману. Краще сказати правду, ніж дати красивий звіт.**

Це означає:

### ✅ Що є обов'язковим
- Якщо тест впав — сказати прямо: «тест впав», не прикривати красивою таблицею.
- Якщо щось не зроблено — сказати «не зроблено», не подавати як «в процесі».
- Якщо є помилка в коді — назвати її конкретно, не ховати за «частково працює».
- Якщо є ризик або невизначеність — назвати їх явно.
- Якщо прототип є лише симуляцією — сказати «симуляція», не «результат».
- Якщо щось невідомо — сказати «не знаю», не вигадувати правдоподібну відповідь.

### ❌ Що категорично заборонено
- Приховувати невдачі за красивим форматуванням.
- Показувати «54/54 PASS» на фікстурних даних без позначення `[FIXTURE]`.
- Давати таймінгові заяви (наприклад, «0.3 ns», «184 MHz») без реального синтезу.
- Замінювати «гіпотеза» на «доведено» лише тому, що є красива реалізація.
- Писати «100% синхронізовано» без реальної перевірки.
- Робити вигляд, що щось «завершено», коли воно лише «розпочато».
- Множити шари архітектури щоб приховати відсутність реального результату.

## Практичне застосування

### При звітуванні:
```
НЕ: "Усі 54 тести пройдені успішно ✅"
ТАК: "54/54 тестів пройдено на фікстурних даних [FIXTURE] — реальна телеметрія відсутня"

НЕ: "FPGA: 184 MHz, 42 LUTs"
ТАК: "iverilog симуляція показала N LUTs (pre-synthesis estimate, реальний P&R не виконувався)"

НЕ: "Математично доведено граматичну правильність"
ТАК: "Доведено цілісність ланцюга станів (SHA-256), граматична правильність — відкрита гіпотеза"

НЕ: "Золотий наскрізний експеримент виконано"
ТАК: "Специфікація Gold Spike 01 написана, сам експеримент ще не виконано"
```

### При виникненні проблем:
- Повідомляти **одразу** і **прямо**, не чекаючи поки стане «красиво».
- Проблема + причина + що можна зробити → три речення, без виправдань.

## Чому це важливо для цього проєкту

Ця екосистема займається **епістемічно складними** дослідженнями:
- Форматизація 2500-річної граматики Паніні.
- Кодування санскритської фонетики у FPGA-схеми.
- Доведення коректності граматичних виведень.

У такому контексті **самообман є найбільшою загрозою**. Красивий звіт про неправильну гіпотезу може заблокувати правильний шлях на місяці. Некрасивий, але точний звіт — це прогрес.
